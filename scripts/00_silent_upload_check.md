# 第 0 步：验「上传不打破静默」

这是整个项目的地基。「打印机在触发前一无所知」是本项目唯一的存在理由——
如果上传动作本身就会唤醒机器发出声音，v0.1 的架构从第一天就是错的。

不写代码，10 分钟。

## 步骤

1. 打印机上开启 **LAN Only 模式**，记下屏幕显示的 **Access Code**、**IP**、**SERIAL**。
   （A1/A1 mini 要先开 LAN Only 才看得到 Access Code；若显示全 0，关掉再开一次。）
2. 顺手把 **Developer Mode** 也开了（第 3 步要用）。
3. 打印机处于 idle。人站在书房里，功率计接好，读数应在 5W 附近（220V 输入下 A1 空闲功耗）。
4. 用任意 FTP 客户端（或第 1 步的脚本 / 下面的 curl）传一个**大** 3mf 上去：

   ```bash
   curl --ftp-ssl --insecure --user "bblp:ACCESS_CODE" -T model.gcode.3mf "ftps://PRINTER_IP:990/"
   ```

5. 上传全程盯着：
   - [ ] 有没有声音（风扇、电机、任何动静）
   - [ ] 屏幕有没有亮起或切换界面
   - [ ] 功率计读数有没有离开 5W 基线
   - [ ] Bambu App / `bpq status` 里状态是否仍是 idle

## 判据

四项全部「无变化」→ 地基成立，`upload_timing = "early"`（提交时就传）。

任意一项有反应 → 地基不成立，改 `upload_timing = "late"`：
文件留在本地，到点才传+立即启动。代价是大文件上传耗时与失败风险全部压进触发时刻，
容错设计要重做。
